### supabase/functions/cleanup/index.ts

#### [WARNING] User folders beyond the first page are never scanned
- **Location:** line 100
- **Issue:** The root listing requests up to 1,000 user folders but does not paginate. If the bucket contains more than 1,000 user folders, all later users' stale metadata files are permanently skipped by every cleanup run.
- **Suggestion:** Page through the root listing using the same `limit`/`offset` loop used for each user's files, or otherwise continue requesting pages until a page contains fewer than the page size.

#### [WARNING] Offset pagination skips files after deletions
- **Location:** lines 112-135
- **Issue:** The function deletes matching files while iterating through offset-based pages. After deleting an item, subsequent items shift earlier, so advancing `offset` by 1,000 can skip stale files that move into the already-processed range. Those files remain until a later run, and repeated deletions can leave a persistent subset unprocessed.
- **Suggestion:** List each user's files without advancing the offset while deleting, or first collect all stale paths and delete them after pagination completes. Collecting paths before removal also avoids mutating the paginated result set.
